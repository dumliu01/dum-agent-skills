# 异常用例 Checklist

> 用途：指导 `dum-server-api-test` 技能阶段②「用例设计」，按接口语义从下列 checklist 中勾选适用的异常场景，并给出各类的断言要点。
> 本文件是**方法论 reference**，不含可运行实现代码。

---

## 使用规则

- **每个接口至少 1 条正常流程用例**（核心正常流程，优先级通常为 P0）。
- **按接口语义从下列 5 类中选取 ≥1 条适用的异常用例**——不是每类都套用到每个接口，只勾选该接口实际存在的语义场景（例如无鉴权的公开接口不需要「鉴权类」）。
- 每条异常用例都要落一个明确的**断言要点**：期望返回码非零（`code != 0`）、期望某个特定错误码、或期望调用直接返回 `err != nil`（如网络层/参数校验层直接拒绝）。

---

## 1. 鉴权类

| 场景 | 说明 | 断言要点 |
|---|---|---|
| 无 token/签名 | 请求不带任何鉴权凭证 | 期望特定错误码（如"未认证"），`code != 0` |
| 错误签名/token | 凭证格式正确但值无效 | 期望特定错误码（如"鉴权失败"） |
| 过期 | 凭证已过有效期 | 期望特定错误码（如"凭证过期"） |
| 越权（他人资源） | 用合法凭证访问不属于自己的资源 | 期望特定错误码（如"无权限"），不应返回他人数据 |

## 2. 参数类

| 场景 | 说明 | 断言要点 |
|---|---|---|
| 必填缺失 | 必填字段不传或传空 | `code != 0`，或客户端层直接 `err != nil` |
| 类型错误 | 字段类型与契约不符（如数字字段传字符串） | `code != 0` 或反序列化 `err != nil` |
| 超长/超短 | 字段长度超出/低于约束范围 | 期望特定校验错误码 |
| 越界值 | 数值超出允许范围 | 期望特定校验错误码 |
| 非法枚举 | 枚举字段传入未定义的值 | 期望特定校验错误码 |
| 空数组/空串 | 期望非空的数组/字符串传空 | 期望特定校验错误码 |

## 3. 幂等/冲突类

| 场景 | 说明 | 断言要点 |
|---|---|---|
| 重复创建 | 用相同唯一键重复调用创建接口 | 期望冲突错误码，或验证幂等返回同一资源 |
| 重复删除 | 对已删除资源再次调用删除 | 期望"资源不存在"类错误码，`code != 0` |
| 并发达到限流 | 短时间内并发调用触发限流 | 期望限流错误码；仅在接口明确有限流策略时纳入 |

## 4. 依赖类

| 场景 | 说明 | 断言要点 |
|---|---|---|
| 依赖资源不存在 | 引用了从未创建过的资源 ID | 期望"资源不存在"类错误码 |
| 依赖资源已删除 | 引用的资源存在过但已被删除 | 期望"资源不存在"或"已删除"类错误码 |
| 顺序颠倒 | 未满足前置步骤就调用（如未创建父资源就创建子资源） | 期望依赖类错误码，或 `err != nil` |

## 5. 状态机类

| 场景 | 说明 | 断言要点 |
|---|---|---|
| 非法状态转移 | 资源当前状态不允许该操作（如未启动就发消息、已结束的任务再次启动） | 期望"状态非法"类错误码，`code != 0` |

---

## 覆盖原则

- 每个接口：**至少 1 条正常 + 按语义选 ≥1 条异常**。
- 不要为了凑数勾选不适用的类别（例如无状态机语义的接口不必造「非法状态转移」用例）。
- 若某类异常在目标接口下无法安全触发（例如触发限流会影响测试环境稳定性），可跳过并在用例文档中注明跳过理由，而不是强行造用例。
